# Target 조회 검토 (2026-09-07)

## 결론

첨부 목록의 네 항목은 OCR에서 모두 추출되었다. 빠진 세 항목은 이미지 디코더 문제가 아니라 **상품 조회 단계에서 이미지 URL을 얻지 못한 것**이다. 기존 Target 검색 API는 세 검색어 모두 403을 반환했고, 공개 검색 HTML은 200이지만 상품 PDP·이미지 데이터가 없었다. 코드만으로 접근 권한을 부여하거나 Render 배포 후 성공을 보장할 수 없다.

| 입력 | 기존 결과의 이유 |
|---|---|
| `big notebook` | API 접근 거부; 저장된 `composition notebook` 키와도 일치하지 않음 |
| `crayon` | 저장된 `crayons` 샘플과 부분 일치; 실시간 조회 성공이 아님 |
| `shoes for running` | API 접근 거부; 저장된 카탈로그에 없음 |
| `bicycle` | API 접근 거부; 저장된 카탈로그에 없음 |

AVIF 지원은 **이미 얻은 이미지 바이트**를 PNG로 디코딩하는 별도 단계다. 상품 검색에서 URL을 못 얻는 문제를 해결하지는 않는다.

## 수정 사항

- 복사된 웹사이트 API 키를 제거했다. 서버의 `CURATOR_TARGET_REDSKY_KEY`가 없으면 검색·PDP·재검토 모두 RedSky를 호출하지 않는다. 이 설정은 운영자가 Target의 승인을 받은 경우에만 사용한다. 임의 키를 넣는 것만으로 접근 권한이 생기지 않는다.
- 실제 요청은 고정 애플리케이션 식별자를 사용한다. 브라우저 지문 변경이나 세션 교체로 403을 재시도하지 않는다. 레거시 세션 메타데이터는 호환 목적으로 남아 있지만 요청 헤더를 결정하지 않는다.
- 검색/PDP/재검토가 같은 요청 정책을 공유한다. 401/403이면 해당 호스트의 추가 요청을 서비스 수명 동안 중단한다. 권한 문제가 해결된 뒤 운영자가 프로세스를 재시작해야 한다.
- 429의 `Retry-After` 초·HTTP 날짜를 존중한다. 해석할 수 없는 헤더는 403으로 오인하지 않고 재요청을 중단한다. 헤더가 없으면 최소 60초 대기한다.
- 접근 거부·요청 한도·시간 초과·상위 서버 장애·응답 형식 오류·상품 데이터 부재를 구분한다. API 오류가 빈 HTML fallback에 가려지지 않는다. 응답 본문·키·요청 URL은 오류 메시지에 포함하지 않는다.
- 동일 검색의 동시 요청을 합치고, 실패/빈 결과를 30초 캐시한다. 알 수 없는 항목에 전체 검색을 두 번 실행하던 경로를 제거했다.
- 일부 항목이 실패해도 OCR 목록의 개수와 순서를 보존한다. 저장된 상품을 쓰면 실시간 확인이 아니라는 설명을 붙인다.
- 서버 환경의 새 API 키도 Flutter 실행기에서 제거한다. Core/BLoC에 Flutter 의존성을 추가하지 않았다.

## 검증과 한계

회귀 테스트는 API 비활성화, 403 요청 중단, 429 대기, 중복 요청 제거, 네 항목 보존, 서버/클라이언트의 안전한 오류 전달을 검사한다. mock 성공은 실제 Target 접근 성공의 증거가 아니다. 기존에 `null`이어도 통과하던 네트워크 테스트를 결정적인 mock·명시적 결과 검증으로 교체했다.

선택적인 실제 HTML 진단은 다음과 같다. 기본 테스트에서는 실행하지 않는다.

```bash
CURATOR_TEST_TARGET_HTML=1 dart test test/target_access_policy_test.dart \
  --name 'live public HTML diagnostic'
```

이 진단은 RedSky를 호출하지 않으며 성공/미해결 결과를 출력한다. 현재 공개 HTML에서 세 품목을 복구하지 못하는 제한은 남아 있다. 공개 페이지의 정상 HTTP 상태만으로 상품 데이터나 자동 조회 권한을 추정하지 않는다.

장기적으로는 Target 승인 상품 피드/API 또는 사용자가 확인한 상품 데이터를 가져오는 별도 어댑터가 필요하다. 현재 공식 피드 연동은 구현되지 않았고, 자동 검색 정상 동작을 선언하지 않는다. Target의 [이용약관](https://www.target.com/c/terms-conditions/-/N-4sr7l)과 [Partners 조건](https://partners.target.com/termsandconditions)을 확인한 범위에서 연동해야 한다.

## 적용

실행 중인 사용자의 백엔드는 자동 재시작하지 않았다. 변경을 적용하려면 해당 Dart 서버와 Flutter 앱을 종료한 뒤 다시 실행하고 문서 파이프라인을 다시 시작한다. Render 배포는 보류 중이다.

## 로컬 검증 결과

- `flutter analyze`: 오류 없음.
- `CURATOR_TEST_AVIF=1 flutter test --concurrency=1 --reporter expanded`: 275개 통과, 선택 실행 테스트 3개 제외.
- `bash tool/flutter_without_server_secrets.sh build web --release`: 성공. 공개 샘플 에셋 31개만 포함하며 개인 업로드는 포함하지 않음.
- `dart compile exe server/curator_proxy_server.dart`: 성공.

이 검증은 실제 Render 배포나 Target 자동 검색 복구를 의미하지 않는다. 병렬 부하에서 불안정하던 네이티브 프로세스 시작 대기 테스트와, 후보 응답을 취소 완료로 오인하던 BLoC 테스트도 보완했다. 샘플 삭제 중단 건은 사용자 승인에 따라 문서와 연결 에셋 25개를 복구했다. 개인 업로드·그 밖의 휴지통 자료는 공개하지 않는다.
